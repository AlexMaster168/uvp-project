# УВП — управление временем проектов

УВП объединяет проекты, задачи и подзадачи, оценки времени, команду, финансы, доступы и медиафайлы. Рабочие экраны дополняют интерактивная структура и отчёты для руководства: прогресс, сроки, риски и оставшаяся нагрузка по людям.

[Открыть приложение](http://167.233.82.147/projects/) · [Тёмная сводка проектов](http://167.233.82.147/projects/?mode=3) · [Светлая сводка проектов](http://167.233.82.147/projects/?mode=4)

## Режимы просмотра

В списке проектов режим выбирается в меню **«Вигляд»**, внутри проекта — в выпадающем списке **«Вид проєкту»** над содержимым. Прежние рабочие экраны сохранены. Выбор запоминается в браузере отдельно для списка и для каждого проекта.

| Режим | Список проектов | Внутри проекта |
| --- | --- | --- |
| **1** | Карточки с обложками, владельцами, задачами и прогрессом работ | Рабочий обзор с вкладками |
| **2** | Компактные карточки без обложек | Интерактивная структура задач и связей |
| **3** | Тёмные компактные сводки проектов для руководства | Тёмный отчёт с компактными строками задач |
| **4** | Светлые карточки проектов с показателями и нагрузкой | Светлый подробный отчёт с карточками задач и рисками |
| **5** | Таблица проектов с настраиваемыми столбцами | Современный обзор: карточки задач |
| **6** | Доска проектов по статусам | Современный обзор: строки задач |
| **7** | Современный светлый обзор проектов | Доступны режимы проекта 1–6 |

Поиск, фильтры по статусу и владельцу, а также пагинация сохраняют выбранный режим. Из сводки списка можно открыть отчёт проекта или подробности задач. Внутри отчёта доступна кнопка **«Друк / PDF»** для печати средствами браузера.

### Персонализация каждого вида

Подробная персонализация доступна **только администраторам**: суперпользователю и пользователям группы `admin`. Обычные пользователи сохраняют рабочие экраны и выбор вида, а новые детальные меню настроек им не показываются. Настройка оформления не расширяет доступ к данным.

В меню **«Вигляд»** администратор сохраняет настройки **отдельно для каждого из семи режимов**. Фото, участники, список задач и финансы работают во всех раскладках, включая компактные карточки. В сводках, таблице и доске дополнительно настраиваются прогресс, сроки, результаты и нагрузка. В таблице скрываются и заголовки, и соответствующие ячейки столбца. Финансовые блоки по умолчанию скрыты: в обычных карточках вместо акцента на деньгах показываются выполненные работы, остаток, риски и дедлайн.

Для каждого вида можно независимо выбрать стандартную тему или одну из четырёх дополнительных: **«Океан»**, **«Лес»**, **«Графит»**, **«Песок»**. Кнопка сброса возвращает стандартные настройки только текущего режима. Старые настройки обычных карточек сохраняются при обновлении.

В современном обзоре переключатель **«Вид 1 / Вид 2»** меняет карточки задач на широкие строки. Для каждой раскладки отдельно сохраняются тема и видимые блоки; настройки также разделены между проектами. Поиск фильтрует задачи по названию и имени исполнителя. Все предпочтения хранятся в текущем браузере.

![Персонализация вида: темы и переключатели блоков](docs/image/22_project_personalization.png)

### Настройка каждой страницы для администратора

Панель **«Налаштувати сторінку»** доступна в проектах, задачах, подзадачах, финансах, доступах, медиафайлах, пользователях, профиле, настройках, дашборде и обеих структурах. Она позволяет выбрать тему страницы, компактную плотность и увеличенный текст, скрыть доступные блоки и необязательные столбцы таблиц. Заголовки записей и действия остаются доступными; обязательные поля форм не скрываются.

Предпочтения этой панели разделены по пользователю, разделу и виду и сохраняются в текущем браузере. Сброс затрагивает только текущую страницу. В списке проектов и современном обзоре остаются отдельные настройки конкретной раскладки в меню «Вигляд».

## Как считаются показатели

В современных карточках и строках показываются **план**, **затрачено** и **ещё работать** для каждой задачи и проекта в целом. Владелец может перейти по ссылке «Змінити оцінку» в форму задачи и выбрать единицу ввода: часы или человеко-дни. При смене единицы уже введённые числа пересчитываются; 2,5 человеко-дня соответствуют 20 часам. Существующие часовые оценки сохраняют прежний смысл. Отдельных изменений базы данных для этого не требуется.

![Оценка задачи в рабочих днях](docs/image/29_task_workdays.png)

- **Прогресс отчёта** — доля выполненных подзадач; задача без подзадач считается одной работой. Завершённая задача считается полностью выполненной. В карточках списка и управленческих отчётах используется один расчёт выполненных работ; количество задач показывается отдельно.
- **Остаток работы** — плановые минус фактические часы незавершённых задач, не меньше нуля. Один человеко-день равен **8 часам**.
- **Нагрузка по людям** — остаток часов задачи делится поровну между назначенными исполнителями. Неназначенная работа показывается отдельно.
- **Риск** — плановые часы израсходованы, но задача ещё открыта. Такая задача требует переоценки; нулевой расчётный остаток не означает, что работа завершена.
- **Дедлайн** — дата окончания проекта. Отсутствующая дата и задачи без оценки обозначаются явно.

Отдельные положительные и отрицательные результаты работ, а также плановая дата смены статуса пока не ведутся. Риски не подменяют отрицательные результаты. Отчёты показывают текущее состояние, а не прогноз сроков. Показатели списка относятся к проектам текущей страницы с учётом фильтров.

Отчёты используют доступные пользователю проекты. Заказчик получает сводку без списка внутренних задач; детальный список задач в режиме 4 ему не показывается.

## Остальные возможности

- Проекты: статусы, теги, владельцы, участники и заказчики.
- Задачи и подзадачи: исполнители, зависимости, плановые и фактические часы.
- Финансы: доходы, расходы и баланс по проектам.
- Доступы и медиафайлы: записи и вложения, связанные с проектом.
- Супер-структура: глобальная карта проектов и владельцев.
- Настройки: язык интерфейса и тема оформления.

## Задачи и подзадачи

В списке задач есть кнопка **«+ Нове завдання»**, поиск и фильтры по проекту и статусу. При создании выбирается доступный проект; список исполнителей обновляется для него. В строке проекта доступна ссылка на редактирование для владельца или администратора с соответствующими правами.

<img src="docs/image/30_tasks_mobile.png" alt="Задачи на телефоне: создание, фильтры и действия" width="390">

В списке и на странице задачи доступны редактирование и удаление. Перед удалением показываются задача, проект и количество подзадач, которые будут удалены вместе с ней. Существующие права создателя, владельцев и участников проекта сохраняются.

![Подтверждение удаления задачи](docs/image/47_task_delete.png)

Во вкладке «Завдання» внутри проекта расширена таблица: статус, название, исполнители, план/факт в часах, прогресс, число подзадач, остаток в человеко-днях и действия. Неизвестная оценка отмечается отдельно, задачи с превышенным планом — риском. Можно открыть задачу, добавить подзадачу, изменить или удалить запись. Необязательные столбцы администратор настраивает через персонализацию страницы.

![Расширенная таблица задач проекта](docs/image/43_project_tasks.png)

<img src="docs/image/45_project_tasks_mobile.png" alt="Расширенная таблица задач проекта на телефоне" width="390">

Из задачи можно открыть любую подзадачу, добавить новую или изменить существующую. У подзадачи есть отдельная страница, форма редактирования статуса и исполнителей, удаление с подтверждением и ссылки обратно к задаче и проекту.

![Страница задачи и действия с подзадачами](docs/image/31_task_detail.png)

![Отдельная страница подзадачи](docs/image/32_subtask_detail.png)

![Редактирование подзадачи](docs/image/33_subtask_form.png)

При создании задачи можно сразу перечислить подзадачи — по одной в строке. При создании проекта можно указать первую задачу и её подзадачи. Эти поля необязательны; записи создаются вместе с родителем.

![Первоначальные задачи и подзадачи при создании проекта](docs/image/34_project_initial_steps.png)

Редактирование задач доступно создателю, владельцам и участникам соответствующего проекта. Заказчик видит общую сводку, без внутренних задач. Проверки проекта и исполнителей действуют в формах и API задач: подстановка чужого идентификатора не предоставляет доступ. Операции изменения пользователей через API доступны только суперпользователю; обычный пользователь не может назначить себе роль администратора.

## Технологии

Python, Django, Django REST Framework, Jinja2, Bootstrap 5, JavaScript, PostgreSQL. Для изолированных тестов используется SQLite. Развёртывание — Docker; маршрутизация приложения на сервере — через инфраструктуру Coolify.

## Локальный запуск

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Параметры базы данных и Google OAuth задаются в локальном `.env`; подробности — в [инструкции по развёртыванию](DEPLOYMENT.md). Без настройки внешней базы приложение по умолчанию использует SQLite. Файлы с доступами и `.env` не предназначены для публикации.

### Проверка отчётов

Тесты покрывают расчёты остатка и рисков, завершённые задачи, неизвестные оценки, отображение режимов, доступ к проектам, ограничения заказчика, фильтры и пагинацию.

Запуск с отдельной SQLite-базой в памяти, PowerShell:

```powershell
$env:DB_ENGINE = 'django.db.backends.sqlite3'
$env:DB_NAME = ':memory:'
python manage.py test apps.projects apps.tasks apps.billing
```

Проверка включает **40 тестов**: расчёты времени, прежние часовые оценки, виды проектов, финансы, группировку по статусам, создание задач и подзадач, начальные работы проекта, права в формах и API, роль администратора и наличие персонализации во всех основных разделах. Новые проверки покрывают создание, редактирование и удаление финансов и доступов, выбор проекта, ошибки форм, ограничения владельцев и участников, подтверждение удаления задач, расширенную таблицу и пагинацию. В браузере дополнительно проверяются переходы по кнопкам, выбор проекта, скрытый пароль и мобильная вёрстка.

### Добавление новых видов

Названия и типы раскладок списка собраны в [реестре представлений](apps/projects/presentation.py), в `PROJECT_LIST_MODES`. Раскладки задач современного обзора задаются в `REPORT_TASK_LAYOUTS`; меню строятся из этих списков. У нового вида должен быть уникальный идентификатор: он также используется для отдельного хранения персонализации.
